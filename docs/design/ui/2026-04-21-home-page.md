# Home Page

## Overview

Replace the empty `MainPage` stub with a curated home page featuring horizontal album carousels. Five sections surface different facets of the library: **Recently Played**, **Recently Released**, **Recently Added**, **Most Played**, and **Random Picks**. Each section is a horizontally scrollable row of album cards reusing the existing album card pattern from `AlbumsPage`.

## Data Sources

All sections use `GetAlbumList2Async` (ID3-tag-based) with different `type` values. The Subsonic API defines these list types:

| Section | API `type` | Notes |
|---|---|---|
| Recently Played | `recent` | Albums ordered by last played date. Requires scrobble data on the server. |
| Recently Released | `byYear` | `fromYear` = current year, `toYear` = 0. Descending year order — returns albums from newest to oldest release year. |
| Recently Added | `newest` | Albums ordered by date added to the library. |
| Most Played | `frequent` | Albums ordered by play count. Requires scrobble data on the server. |
| Random Picks | `random` | Random selection of albums, refreshed on each page load. |

Each section requests **20 albums** per call (`size=20`). No pagination — the home page is a curated snapshot, not an exhaustive listing.

### Recently Released — Year Range Strategy

"Recently released" uses `type=byYear` with `fromYear` set to the current calendar year and `toYear` set to 0. This relies on documented Subsonic API behavior:

> **fromYear**: *"The first year in the range. If fromYear > toYear a reverse chronological list is returned."*
> — [Subsonic API](https://www.subsonic.org/pages/api.jsp), [OpenSubsonic API](https://opensubsonic.netlify.app/docs/endpoints/getalbumlist2/)

By passing `fromYear=2026, toYear=0`, the server returns all albums ordered by year descending (newest first), which is exactly the "recently released" sort. This is the same approach used by Feishin (`subsonic-controller.ts`, lines 717–725). It avoids client-side filtering or multi-request fallback — the server handles both filtering and ordering in a single call.

### Empty Sections

A section that returns zero albums is hidden entirely (`Visibility.Collapsed`). This handles libraries without scrobble data (Recently Played and Most Played will be empty) or without recent releases. If all five sections are empty (unlikely but possible for a brand-new server), the page shows a centered message: "Your library is waiting — start playing some music!"

The entire page is a vertical `ScrollViewer` containing stacked sections. Each section has a header and a horizontal carousel.

### Album Card

Reuse the full album card template from `AlbumsPage.xaml`, including the segmented artist rendering. Fixed card width of **180px** (slightly narrower than the grid layout on `AlbumsPage`, optimized for horizontal scrolling where more items should be visible at once).

Card content:
- **Cover art**: `BitmapImage` from `SubsonicClient.GetCoverArtUri(album.CoverArt, "300")` — note: the `CoverArt` field from `AlbumID3` is passed, **not** the album `Id` (they can differ)
- **Title**: Album name, single line, trimmed with ellipsis
- **Artist**: `RichTextBlock` with segmented artist rendering via `DisplayArtistRenderer.BuildSegments` and `AlbumArtistLinks_DataContextChanged`, matching `AlbumsPage`. Clickable artist hyperlinks navigate to `ArtistDetailPage`. This preserves the artist-album navigation consistency work.
- **Year**: Tertiary text below artist

The card template, including the `DataContextChanged` handler for artist links, the `SecondaryBrushProvider`/`TertiaryBrushProvider` brush elements, and the `ActualThemeChanged` rerender hook, should be extracted into a shared pattern or duplicated with the same code-behind helpers used in `AlbumsPage.xaml.cs` (artist link click handling, segment rendering). The exact extraction strategy (shared `UserControl` vs. duplicated template + code-behind) is an implementation decision.

### Horizontal Carousel

Each section uses a `ScrollViewer` with horizontal scrolling (`HorizontalScrollBarVisibility="Auto"`, `VerticalScrollBarVisibility="Disabled"`) wrapping an `ItemsRepeater` with a `StackLayout` (`Orientation="Horizontal"`, `Spacing="8"`).

**Why `ScrollViewer` + `ItemsRepeater`**, not a `ListView` with horizontal orientation: `ItemsRepeater` with `StackLayout` gives direct control over spacing and avoids `ListView`'s selection/focus behaviors that aren't needed here. The built-in scroll viewer provides touch panning, mouse wheel horizontal scroll (with Shift held), and scrollbar visibility.

### Section Header

Each section header is a `TextBlock` with `Style="{StaticResource SubtitleTextBlockStyle}"` and `Margin="0,24,0,12"` (top spacing between sections, bottom spacing before cards). The first section uses `Margin="0,0,0,12"` (no top padding).

### Card Interaction

- **Click**: Navigate to `AlbumDetailPage` with the album ID, same as `AlbumsPage.AlbumCard_Click`
- **No right-click context menu**: Out of scope (same as the rest of the app)

### Loading State

A single page-level `ProgressRing` centered in the content area while data is loading. All five API calls are fired in parallel; the page transitions from loading to content once all calls complete (or fail). Individual section visibility is determined after all data arrives — no progressive section-by-section rendering, which would cause layout shifts.

### Error Handling

Each API call is independently try/catch wrapped. A failed call results in that section being hidden (treated as empty). Only if all five calls fail does the page show an error state: "Couldn't load your library — check your connection and try again" with a Retry button.

## ViewModel Design

### `MainViewModel`

`MainViewModel` must implement `INavigationAware` to receive `OnNavigatedTo`/`OnNavigatedFrom` lifecycle callbacks — this is how the app's `NavigationService` triggers page loading. Without it, the home page will never load data.

```csharp
[ObservableProperty]
private bool isLoading;

[ObservableProperty]
private bool hasError;

[ObservableProperty]
private bool hasAnyContent;

[ObservableProperty]
private ObservableCollection<AlbumInfo> recentlyPlayed = [];

[ObservableProperty]
private ObservableCollection<AlbumInfo> recentlyReleased = [];

[ObservableProperty]
private ObservableCollection<AlbumInfo> recentlyAdded = [];

[ObservableProperty]
private ObservableCollection<AlbumInfo> mostPlayed = [];

[ObservableProperty]
private ObservableCollection<AlbumInfo> randomPicks = [];

// Section visibility derived from collection count
public bool HasRecentlyPlayed => RecentlyPlayed.Count > 0;
public bool HasRecentlyReleased => RecentlyReleased.Count > 0;
public bool HasRecentlyAdded => RecentlyAdded.Count > 0;
public bool HasMostPlayed => MostPlayed.Count > 0;
public bool HasRandomPicks => RandomPicks.Count > 0;

[RelayCommand]
private async Task RetryAsync() => await LoadSectionsAsync();
```

The `RetryAsync` command backs the error-state Retry button, calling the same `LoadSectionsAsync` method used by `OnNavigatedTo`.

### Model

Reuse the existing `Hypersonic.Core.Models.AlbumInfo` — the same type that `AlbumsPage` and `ArtistDetailPage` already bind. It carries all needed fields: `Id`, `Name`, `Artist`, `ArtistId`, `CoverArt`, `CoverArtUrl`, `Year`, `DisplayArtist`, `Artists`, `HasStructuredArtists`.

The `AlbumID3` → `AlbumInfo` mapping (including `SongArtistMapper.MapArtists` for structured artist data and `GetCoverArtUri(album.CoverArt, "300")` for cover art URL) follows the same pattern as `AlbumsViewModel`. This should be extracted into a shared helper in the **Hypersonic assembly** (not Hypersonic.Core, since `AlbumID3` comes from `Hypersonic.Client` and Core avoids a client reference). All three consumers — `AlbumsViewModel`, `ArtistDetailViewModel`, and `MainViewModel` — should use this helper to fully deduplicate the mapping logic.

### Data Flow

1. `OnNavigatedTo` → call `LoadSectionsAsync()`
2. `LoadSectionsAsync`: set `IsLoading = true`, `HasError = false`, clear all collections
3. Fire all five `GetAlbumList2Async` calls via `Task.WhenAll`, each wrapped in try/catch
4. Map results to `AlbumInfo` using the same `AlbumID3` → `AlbumInfo` mapping as `AlbumsViewModel` (including `SongArtistMapper.MapArtists` and `GetCoverArtUri(album.CoverArt, "300")`)
5. For Recently Released: single `byYear` call with `fromYear=currentYear, toYear=0` (reverse chronological per Subsonic API spec)
5. Set `IsLoading = false`
6. Raise `OnPropertyChanged` for all `Has*` properties
7. Set `HasAnyContent` (true if any section has data)
8. If no content and all calls failed → set `HasError = true`

### Refresh

Navigating away and back to the home page triggers a full reload (`OnNavigatedTo`). No manual refresh button — the Random Picks section provides natural variety on each visit. The page does not cache data across navigations since the home page is meant to reflect current state.

## Existing Client Support

| Method | Status | Notes |
|---|---|---|
| `GetAlbumList2Async(type, size, offset, fromYear, toYear, genre, musicFolderId)` | Implemented | ID3-based album list |
| `GetCoverArtUri(coverArtId, size)` | Implemented | Pass `AlbumID3.CoverArt`, not album `Id` |
| `AlbumID3` entity | Implemented | Has `Id`, `Name`, `Artist`, `ArtistId`, `CoverArt`, `Year`, `Artists`, `DisplayArtist` |
| `Hypersonic.Core.Models.AlbumInfo` | Implemented | Shared presentation model with `Artists`, `HasStructuredArtists`, `CoverArtUrl` |
| `SongArtistMapper.MapArtists(...)` | Implemented | Maps `AlbumID3.Artists` to structured `SongArtistInfo` list |

The `type` parameter accepts string values defined by the Subsonic API: `"random"`, `"newest"`, `"frequent"`, `"recent"`, `"byYear"`. These are passed as plain strings to `GetAlbumList2Async`.

## Scope

- Replace `MainPage` empty grid with home page layout
- `MainViewModel` implements `INavigationAware` with `RetryCommand`
- Reuse existing `Hypersonic.Core.Models.AlbumInfo` — no new model
- Extract shared `AlbumID3` → `AlbumInfo` mapping helper in Hypersonic assembly (used by `AlbumsViewModel`, `ArtistDetailViewModel`, and `MainViewModel`)
- Implement `MainViewModel` with five parallel API calls and section visibility logic
- Horizontal carousel sections with full album card template (segmented artist links, cover art via `CoverArt` field, year)
- Recently Released via reverse-chronological `byYear` call
- Loading state, error handling, empty section collapse
- Navigation to `AlbumDetailPage` on card click

## Out of Scope

- "See All" links to filtered album lists (future enhancement)
- Drag-to-reorder sections or user-configurable section visibility
- Pull-to-refresh or manual refresh button
- Song-level carousels (all sections are album-based, matching the Subsonic `getAlbumList2` API)
- Skeleton/shimmer loading placeholders (simple `ProgressRing` is sufficient for MVP)

## Unit Tests

Add `MainViewModelTests` in `Hypersonic.Tests` following the pattern established by `ArtistDetailViewModelAlbumMappingTests` and `ArtistDetailViewModelTopSongsTests` — using a fake `ISubsonicClient` implementation to control API responses.

### Test Cases

**Section population and visibility**:
- All five API calls return data → all five sections populated, `HasAnyContent = true`
- API returns empty array for a section → that section's `Has*` property is `false`
- All sections empty → `HasAnyContent = false`, empty-library message shown

**Recently Released**:
- Uses `byYear` with `fromYear=currentYear, toYear=0` for descending year order
- Returns albums sorted newest to oldest

**Failure isolation**:
- One API call throws `HttpRequestException` → that section hidden, others still populated
- All five calls throw → `HasError = true`, `HasAnyContent = false`
- Mix of failures and empty responses → only successful non-empty sections visible

**Retry**:
- After full failure, `RetryCommand` re-invokes `LoadSectionsAsync` and populates sections on success

**Album mapping**:
- `AlbumID3` with structured `Artists` → `AlbumInfo.Artists` populated, `HasStructuredArtists = true`
- `AlbumID3` without structured artists → falls back to `Artist`/`ArtistId` fields
- `CoverArtUrl` uses `AlbumID3.CoverArt` field (not `Id`)

## Verification Checklist

- **All five sections render** with correct data on a server with scrobble history
- **Empty sections hidden**: New server with no play history → Recently Played and Most Played hidden
- **Recently Released ordering**: Albums sorted by year descending (newest first)
- **All sections empty**: Empty library shows fallback message
- **All calls fail**: Network error shows error state with retry
- **Partial failure**: 3/5 calls succeed → those 3 sections render, failed 2 hidden
- **Card click**: Navigates to correct `AlbumDetailPage`
- **Cover art**: Loads correctly, fallback shown for missing art
- **Horizontal scroll**: Mouse wheel (Shift+scroll), touch pan, scrollbar all work
- **Layout**: No layout shifts after loading completes
- **Random Picks vary**: Navigating away and back shows different random albums
- **Performance**: Page loads within ~1s on a local Navidrome server (5 parallel API calls, 20 items each)
