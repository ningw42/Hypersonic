# Win2D Lyrics Control (Phase 2) — Implementation Notes

Companion to the design at [`../../design/ui/2026-06-13-lyrics-canvas-control.md`](../../design/ui/2026-06-13-lyrics-canvas-control.md). Records only what the design does **not** already say: the concrete shape the code took, the conscious deferrals, and the decisions settled during implementation. The design's structure — pure-presentation control, analytic-core + minimal-primitive animation (Approach C), per-row gradient wipe, pre-cache override source — was implemented faithfully and is not re-explained here.

**Status: code complete, all automated tests green; the §7 visual 60 fps smoke test is the remaining gate** (it needs the running WinUI app + a real song, which can't be exercised headless). Committed on `feat/lyrics-canvas-control` and under review.

The analytic core was built test-first (red→green); the Win2D rendering glue is build-verified and exercised through the `Lyrics Lab` harness.

## What shipped, in dependency order

- **Core** (`Hypersonic.Core/Services/Lyrics/`) — `TtmlLyricsConstants` (`"ttml"` tag, owned in Core because the parser and the Hypersonic override source both reference it); `TtmlLyricsParser` (AMLL TTML → `LyricsSyncKind.Word`; `<p>`→line, `<span begin/end>`→word; `ttm:role="x-bg"|"x-translation"|"x-roman"` aux spans dropped for single-lane; namespace-agnostic by local name; validated via `LyricsValidator`). Registered in `App.xaml.cs`.
- **Animation primitive** (`Hypersonic/Controls/Lyrics/`) — `Spring` (closed-form critically-damped, overshoot-free, scroll Y) + `Tween` (first-order eased approach for emphasis; `EaseOutCubic`/`Pulse` statics for analytic bloom).
- **Analytic core** — `PlaybackClock` (anchor + free-run + seek-snap/smooth-converge); `LyricsTimingModel` (offset folding, line-end resolution, synthetic line-only word, `HasWordTiming`); `LyricsSynchronizer` (cached linear scan, O(1) forward); `LyricsWipe` (played-head walk + per-row fraction). All pure, all unit-tested.
- **Win2D model/render** — `LyricsVisualModel`/`LyricsLayout` (wrapping `CanvasTextLayout`; rows + word row-fragments from `GetCharacterRegions`; reading-order pixel spans); `LyricsChoreographer` (spring scroll, emphasis targets, bloom onsets); `LyricsSceneRenderer` (per-row 4-stop gradient wipe, bloom, edge fade).
- **Public surface** — `LyricsCanvasControl` (`UserControl` + `CanvasAnimatedControl`; DPs for `Lyrics`/`PositionMs`/`IsPlaying`/`TrackDurationMs`/colours/font + `EnableBloom`/`EnableNeighborBlur`).
- **Feed-real-data path** — `ILocalLyricsOverrideSource` + `LocalFileLyricsSource` (reads `<songId>.ttml`, parses via the registry); `IAppFolderLocator.GetLyricsOverrideFolder()`; `LyricsService` pre-cache hook; DI registration.
- **Harness** — `LyricsLabViewModel` + `LyricsLabPage` + a temporary `Lyrics Lab` nav entry: a hardcoded `NavigationViewItem` in `ShellPage.xaml` **plus** the `PageService` mapping **plus** the DI registrations. Deleted in Phase 3 — all three removal points, or a dangling nav item remains.

## Decisions settled during implementation

- **TTML dialect = AMLL TTML DB spec** (user's call), to be pinned against a real sample before being relied on (design §3.8/§7). The parser is namespace-agnostic and tolerant of missing `<p>` bounds, so the real file should slot in with at most attribute tweaks.
- **Pure timing core extracted from the visual model.** The design's `LyricsVisualLine` couples timing + text layout; the timing/sync/wipe math was split into device-free classes (`LyricsTimingModel`, `LyricsSynchronizer`, `LyricsWipe`) so it is unit-testable, with `LyricsVisualModel`/`LyricsLayout` layering Win2D on top. The synchronizer resolves against the (parallel) timing lines.
- **Clock "now" = the frame's `Timing.TotalTime`.** `CanvasAnimatedControl` runs its loop on a render thread; making the clock read the frame clock keeps `SetPosition`/`SetPlaying`/`Estimate` all on that thread (no cross-thread clock). DP changes (UI thread) are mirrored into plain fields under a lock and consumed in `OnDraw`.
- **Teardown is gated against the render loop (fix, surfaced post-ship while exercising the harness).** Same render-vs-UI-thread split as the clock, on the destroy path: `CanvasAnimatedControl` raises `Draw` on its game-loop thread, and `RemoveFromVisualTree()` — called from `Unloaded` on the UI thread — only *asks* that loop to stop, it does **not** join the thread. So disposing the frame's `CanvasTextLayout`s / `CanvasTextFormat` straight from `Unloaded` raced an in-flight draw: an intermittent `ObjectDisposedException` out of `DrawTextLayout` when navigating away from Lyrics Lab (only when a frame happened to be drawing at the instant of unload — the race signature). `LyricsRenderGate` serialises the two — `OnDraw` runs the frame *through* the gate, `OnUnloaded` latches-then-disposes *through* it (after `RemoveFromVisualTree`, kept outside the gate so a stopping loop can't deadlock on it), and any frame the loop still raises after teardown no-ops. The gate is a separate lock from the per-frame mirror `_gate`, so a frame-long hold never stalls the frequent DP handlers. Pure threading (no Win2D), so it is unit-tested for the mutual-exclusion and post-teardown-skip contract; the per-frame hop stays allocation-free via a static lambda + tuple state.
- **Override source is an optional trailing ctor param** on `LyricsService` (DI injects the registered one; existing tests pass `null` implicitly) — keeps the one-branch hook isolated without churning the Phase 1/1.5 test call sites.
- **`LyricsFontSize`, not `FontSize`** — a distinct DP rather than hiding the inherited `Control.FontSize`.
- **Word-timing normalization (pinned against a real AMLL sample).** The first real file (amll-ttml-db "Blinding Lights") had one word-start wobble — a syllable beginning 59 ms before the previous zero-duration syllable — which failed the strict `LyricsValidator` monotonicity rule and discarded the whole 37-line song. `TtmlLyricsParser` now normalizes per line (clamp word starts non-decreasing, end ≥ start, line bounds from min-start/max-end across all words) so real community files load; the validator stays strict for the renderer's benefit. The imperceptible few-ms shift is the price of robustness.
- **Static (Plain) lyrics pin to the top.** Their line starts are all 0, so the synchronizer would resolve the *last* line and scroll to the bottom; the choreographer special-cases `IsStatic` to anchor near the top instead (user-scroll lands in Phase 3). `IsStatic` also flattens the *look*: every line draws at full opacity with no active-line highlight, no neighbour dimming/blur, and no bloom — a Plain document has no current-line cue at all, distinct from the per-line emphasis synced lyrics get. (Surfaced by a Navidrome track returning `synced:true` with all-null timestamps → parsed as Plain; the lrclib provider supplies the real sync.)
- **Animation state survives re-layout.** Emphasis tweens + bloom onsets live on `LyricsVisualLine`, which is rebuilt on a width/font change. A naive rebuild reset them every frame, so a live horizontal resize dropped neighbour blur and jittered inactive lines (scale resetting 1.0→0.95 each frame). The control now transfers per-line emphasis + per-word onsets from the old model to the re-laid-out one (parallel by index) and leaves the scroll spring intact, so a resize re-wraps smoothly. A full reset happens only on an actual track change.
- **Alignment-aware scale pivot (caller input beyond the original sketch).** Added an `Alignment` DP (Left/Center/Right) that drives both the text-format alignment and the active-line scale pivot: pivot at the alignment edge (left → left margin, right → right edge, centre → centre) so the emphasised line grows away from that edge instead of sliding sideways. The earlier fixed centre-pivot broke strict left-alignment (inactive lines pulled inward). The wipe was already alignment-correct (it uses each row's real bounds). `LyricsAlign.PivotX` is unit-tested.
- **`EnableKaraokeWipe` caller toggle.** Live DP: `true` (default) = gradient sweep on the active line; `false` = a discrete solid played-colour highlight of the whole line (Spotify-style) with bloom suppressed — useful for line-synced sources whose sweep timing is coarse. Joins `EnableBloom` / `EnableNeighborBlur`; all three apply live, no reload.

## Conscious deferrals (staged per §7 "smoke-test 60 fps before layering bloom/glow")

These are wired but intentionally minimal/off so the perf smoke test layers them on deliberately:

- **Bloom = a seamless scale *swell*** (smoke-test feedback). The word is redrawn **opaque, with the same per-row wipe colouring, scaled about its centre, no vertical float**. The original float-up produced a doubled "shadow" (the at-rest word showing under the lifted, semi-transparent copy); a true lift-without-ghost needs separating the word into its own sprite removed from the base pass — deferred. The glow halo (§5.2 third bullet) is also not yet drawn.
- **Neighbour gaussian blur defaults OFF** (`EnableNeighborBlur`), exposed as a harness toggle; inactive-line depth currently comes from the opacity/scale falloff.
- **Edge fade is a per-line vertical opacity falloff**, not a true gradient-mask layer — cheap and dissolves short lyric lines at the edges; upgradeable to a mask if the smoke test wants a harder dissolve across tall lines.

## Behaviour pinned in code (the design left it open)

Mechanics the design under-specified, settled during implementation — plus two deviations a reviewer should see:

- **The clock is call-once-per-frame.** `PlaybackClock.Estimate()` is *side-effecting* — each call decays the smooth-converge residual and advances its wall-time mark, and `SetPosition` calls it internally — so a frame must evaluate it once and reuse the value (a second read in the same frame double-decays the residual). The converge residual decays on its own `ConvergenceTimeConstantMs` (~120 ms), a second tuning knob independent of the ~250 ms `SeekThresholdMs` seek/smooth cutoff; both are settable.
- **Active-line selection is start-only.** `LyricsSynchronizer` compares position against line `StartMs` only — never the resolved `EndMs` — so a line stays the active (centred/emphasised/scrolled-to) line through any inter-line gap until the next line begins. The resolved line-end feeds the wipe and inactive styling, not selection.
- **Word-order normalization is parse-time only.** `NormalizeWordTimings` lives in `TtmlLyricsParser`; `LyricsTimingModel.Build` folds the global offset but does *not* clamp ordering. `LyricsWipe.PlayedHeadPx` walks words in list order and stops at the first whose start is still ahead of `t`, so any future non-TTML word-level source must pre-sort word starts non-decreasing *before* the timing model, or the wipe truncates early.
- **Inter-word whitespace is load-bearing.** The parser loads with `PreserveWhitespace` and folds genuine literal text between spans onto the *preceding* word's text, so that word's measured pixel extent — and hence the wipe geometry — includes the trailing gap. Only literal runs containing a newline (editor indentation between elements) are trimmed.
- **TTML time forms.** `ParseTime` accepts only `hh:mm:ss.fff`, `mm:ss.fff`, and bare offset-seconds `ss.fff` (optional trailing `s`, stripped only when there is no colon). Frame / tick / percentage forms are unsupported and silently degrade to line-level timing — relevant when pinning the dialect against a richer real sample.
- **Layout constants.** Lines stack with a gap of ~half a single text row (`Height / rowCount × 0.5`, so it stays ~half-row regardless of wrap count); an unbreakable token wider than the viewport scales down *horizontally only*, with a `0.5×` floor below which it is allowed to clip.
- **Deviation — final-line offset fold.** `OffsetMs` is folded into every line/word start and end *except* the final line's last-resort end when it falls back to `TrackDurationMs` (that one branch uses the raw absolute duration with no offset added). Benign today — track duration is already on the same absolute clock and the end is clamped ≥ start — but it is the lone spot that breaks the design's "offset folded into every start/end" rule, and a non-zero-offset source could expose it.
- **Deviation — override folder is resolved, not hardcoded.** The design named `%LOCALAPPDATA%\Hypersonic\LyricsOverride`; the real folder comes from `IAppFolderLocator.GetLyricsOverrideFolder()`, which (mirroring the cache folder) branches on MSIX → `…\Packages\<pkg>\LocalState\LyricsOverride` for the packaged build actually run in dev, falling back to the design's unpackaged path only when not packaged. The harness header shows the live resolved path so the right folder is never in doubt.

## Phase 3 input contract (control + override boundary)

What a future driver must know about the input surface, beyond the design's DP list:

- **No backplate.** The hosted `CanvasAnimatedControl` clears to `Transparent`; the control paints only text and composites over whatever is behind it. The Phase 3 host owns the background / scrim and any contrast guarantee — the control draws none.
- **Colour defaults assume a dark surface.** Left unbound, `PlayedColor = White` and `UnplayedColor ≈ #6EFFFFFF` (≈43 % white) — *not* theme-aware. A light-surface host must bind theme colours explicitly (the harness binds `SystemAccentColor` / `TextFillColorTertiary` to demonstrate the pattern).
- **`FontFamilyName` is a single family, not a fallback list.** It is passed verbatim to `CanvasTextFormat.FontFamily`, which Win2D does not parse as a comma-separated chain — so the caller cannot supply one. Glyphs absent from the chosen family are covered only by the platform's automatic per-glyph fallback (foreign scripts still render; the CSS/XAML family-list shape is simply ignored).
- **The override is sticky and raw.** A present `<songId>.ttml` wins ahead of the cache read — *including* over an explicit `forceRefresh` (a "refresh lyrics" action won't dislodge it; only deleting the file reverts). It is returned exactly as parsed, skipping the cache path's metadata overlay, and the TTML parser sets neither `OffsetMs` nor `LanguageCode` — so any timing correction must be baked into the TTML timestamps themselves. The lookup also requires a filename-safe `songId`: an id carrying a path-invalid character (e.g. `:`) cannot be sideloaded.

## Smoke-test checklist (the §7 hand-off)

1. Build/deploy, play a track, open **Lyrics Lab**. Live providers give Line/Plain → confirm the line-level fill + scroll.
2. Drop `<songId>.ttml` (AMLL word-timed) into the override folder — **the harness header shows the live, resolved path** (packaged: `…\Packages\<pkg>\LocalState\LyricsOverride`; unpackaged: `%LOCALAPPDATA%\Hypersonic\LyricsOverride`). `<songId>` is the Subsonic song id of the playing track. Confirm the intra-word wipe + bloom; if attributes differ, pin `TtmlLyricsParser` to the sample. (No restart needed — the override is checked before the cache on every fetch; just re-enter Lyrics Lab.)
3. Watch the frame rate; then toggle Bloom / Neighbour-blur and tune the §5.3 constants. Exercise a long (wrapping) line and a CJK line.
