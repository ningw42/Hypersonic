# Home Page — Implementation Notes

Companion to [`docs/design/ui/2026-04-21-home-page.md`](../../design/ui/2026-04-21-home-page.md). This document covers implementation-specific decisions, deviations from the design, and details that only appear in source.

---

## AlbumMapper extraction

The design doc calls for extracting the `AlbumID3` → `AlbumInfo` mapping into a shared helper. This was implemented as `Hypersonic.Helpers.AlbumMapper` — a static class with `Map(AlbumID3, ISubsonicClient)` and `MapAll(AlbumID3[]?, ISubsonicClient)` methods. All three consumers (`AlbumsViewModel`, `ArtistDetailViewModel`, `MainViewModel`) now use it.

The mapper uses a type alias (`using CoreAlbumInfo = Hypersonic.Core.Models.AlbumInfo`) to avoid ambiguity since `AlbumInfo` exists in both the Core models and the Client response models.

### Artist field mapping

The `AlbumMapper.Map` method sets `AlbumInfo.Artist` to `album.DisplayArtist ?? album.Artist ?? string.Empty`. This differs slightly from the previous `AlbumsViewModel` inline mapping, which used `album.Artist` directly. The `ArtistDetailViewModel` inline mapping already used the `DisplayArtist ?? Artist` pattern. The mapper now unifies on the `DisplayArtist`-first approach, which is more correct for multi-artist albums.

Similarly, `AlbumInfo.Name` now falls back to `string.Empty` instead of being nullable, matching the `ArtistDetailViewModel` pattern.

## ShowEmptyState guard

The design doc specifies an empty-library message when all sections are empty. The implementation adds a `_hasLoadedOnce` flag and a computed `ShowEmptyState` property:

```csharp
public bool ShowEmptyState => _hasLoadedOnce && !IsLoading && !HasError && !HasAnyContent;
```

This prevents the empty state from flashing on initial page load before any data has been fetched. The flag is set to `true` at the end of `LoadSectionsAsync`, after all data processing completes. `ShowEmptyState` is re-evaluated via `[NotifyPropertyChangedFor]` on `IsLoading`, `HasError`, and `HasAnyContent`.

---

## ObservableCollection as read-only properties

The design doc shows `[ObservableProperty]` on the collection fields. The implementation uses `{ get; } = []` (getter-only auto-properties) instead, avoiding unnecessary property-changed notifications when the collections themselves never change — only their contents do. `IsLoading`, `HasError`, and `HasAnyContent` remain `[ObservableProperty]` since they are value types that change.

Because the collections are mutated in-place (via `Add`/`Clear`) rather than replaced, the computed `Has*` properties don't auto-notify. `LoadSectionsAsync` manually raises `OnPropertyChanged` for each `Has*` property after populating all collections, ensuring the UI updates section visibility in a single batch.

## Null propagation for empty API responses

`FetchSectionAsync` returns `null` on failure (exception caught) and an empty list when the API returns no albums. `PopulateSection` increments a `failureCount` ref counter only for `null` results. This distinction allows the ViewModel to differentiate between "API returned zero albums" (section hidden, not counted as failure) and "API call threw" (section hidden, counted toward the all-failed error state).

## NavigationView header suppression

The XAML sets `behaviors:NavigationViewHeaderBehavior.HeaderMode="Never"` to hide the navigation header on the home page. This is not mentioned in the design doc but follows the pattern of a curated landing page that doesn't need a redundant "Home" header above the content.

---

## Album card template duplication

The design doc notes the extraction strategy (shared `UserControl` vs. duplicated template) is an implementation decision. The implementation duplicates the full `DataTemplate` five times in `MainPage.xaml` — one per section. Each template is identical: `Button` with `SubtleButtonStyle`, card `Border`, `SquarePanel` cover art with fallback icon, title, `RichTextBlock` artist links, and year.

The code-behind (`MainPage.xaml.cs`) duplicates the artist rendering helpers from `AlbumsPage.xaml.cs`: `AlbumArtistLinks_DataContextChanged`, `RenderArtistSegments`, `BuildArtistTooltip`, and the theme-change rerender logic. A shared `UserControl` was not pursued to keep the change set focused on the home page feature.

---

## Theme change rerendering

`MainPage` subscribes to `ActualThemeChanged` and calls `ReRenderAllCarousels()`, which iterates all five `ItemsRepeater`s and resets each element's `DataContext` to force a re-render of artist segments with updated brush colors. The `Unloaded` event unsubscribes the handler to avoid leaks. This matches the pattern established in `AlbumsPage.xaml.cs`.

---

## Card hover styling

Each album card `Button` overrides `SubtleButtonBackgroundPointerOver` and `SubtleButtonBackgroundPressed` via inline `ThemeDictionaries` to provide subtle hover/press feedback with semi-transparent overlays (`#1A000000` / `#1AFFFFFF` for light/dark themes). This is a visual polish detail not specified in the design doc.

## Localization

All user-facing strings use `x:Uid` bindings to `Resources.resw` entries (`Home_RecentlyPlayed`, `Home_RecentlyReleased`, `Home_RecentlyAdded`, `Home_MostPlayed`, `Home_RandomPicks`, `Home_Error`, `Home_Retry`, `Home_Empty`). The `Text` attributes in XAML serve as design-time fallbacks. This follows the existing localization pattern.

---

## Client null guard

`LoadSectionsAsync` and both `Fetch*Async` methods check `_subsonicClientService.Client` for null before proceeding. If the client is null (disconnected state), the method returns early without setting error state. The design doc doesn't address disconnected state explicitly.

---

## LoadSectionsAsync is internal

`LoadSectionsAsync` is marked `internal` rather than `private` to allow direct invocation from unit tests, bypassing the `async void OnNavigatedTo` entry point. Tests call `await vm.LoadSectionsAsync()` directly for deterministic assertions.

---

## Test infrastructure

Tests use a `FakeSubsonicClient` with a `Dictionary<string, AlbumID3[]?>` for response lookup and a `HashSet<string>` for types that should throw `HttpRequestException`. The dictionary key for "Recently Released" is `$"byYear:{DateTime.Now.Year}-0"`, matching the actual API call parameters. This allows tests to verify the correct `fromYear`/`toYear` values are passed.

A `NullLogger` / `NullLoggingService` pair suppresses logging in tests. Both follow the existing test pattern from `ArtistDetailViewModelTests`.

### Test coverage vs. design doc

Most test cases from the design doc's "Unit Tests" section are covered:
- Section population and visibility (all populated, partial empty, all empty)
- Recently Released year ordering
- Failure isolation (partial failure, all fail)
- Retry after failure
- Album mapping (`CoverArt` vs `Id`, `DisplayArtist` fallback)
- Additional: `ShowEmptyState` guard before first load

**Not covered:**
- Structured artist mapping (`AlbumID3` with `Artists` → `AlbumInfo.HasStructuredArtists = true`) — the design doc calls for this but no test asserts it
- Mixed failures and empty responses in a single test — the partial failure test uses thrown exceptions only, not a mix of exceptions and empty arrays
